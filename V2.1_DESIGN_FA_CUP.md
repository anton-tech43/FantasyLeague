# V2.1 Design — FA Cup coverage in match-watcher

**Status:** Design only. Not implemented. Not launch-blocking.
**Owner:** Backend (Edge Functions + migration).
**Cost estimate:** ~1 hour to ship.

## Problem

`match-watcher` polls API-Football for fixture transitions (NS → FT/AET/PEN) to fire `gd-matchday`. Today it derives the league set from `SELECT DISTINCT league_id FROM teams`, which returns `[39, 1]` (Premier League + FIFA World Cup). FA Cup is `league_id = 45`. Every PL club participates in the FA Cup, but their FA Cup fixtures aren't picked up by the watcher because no team row has `league_id = 45`.

Result: when Arsenal play Manchester City in the FA Cup semi-final, `gd-matchday` doesn't fire. Users miss the post-match brief.

The same gap will exist for any future cup competition (Carabao Cup `league_id = 48`, Champions League `league_id = 2`, Europa League `league_id = 3`) and for the WC playoffs (which API-Football may classify under a different league_id when scheduled in 2030).

## Solution shape

Add a many-to-many relationship between `teams` and competitions. Migrate from "one league_id per team row" to "a team participates in N competitions."

### Option A (recommended) — JSONB column on `teams`

Add `competitions JSONB DEFAULT '[]'::jsonb` to `teams`:

```sql
ALTER TABLE teams ADD COLUMN competitions JSONB NOT NULL DEFAULT '[]'::jsonb;

-- Backfill: PL clubs get [39, 45] (PL + FA Cup). Future: add 48 for League Cup, 2 for CL.
UPDATE teams SET competitions = '[39, 45]'::jsonb WHERE entity_type = 'club';

-- Countries get [1] (WC only for now).
UPDATE teams SET competitions = '[1]'::jsonb WHERE entity_type = 'country';
```

Then in `match-watcher` (and `matchday-scheduler`, and any other Edge Function that builds the active-leagues list):

```typescript
// OLD: const { data: leagues } = await supabase.from('teams').select('league_id').not('league_id', 'is', null);
// const uniqueLeagues = [...new Set(leagues.map(l => l.league_id))];

// NEW: collect all distinct league IDs across all teams' competitions arrays
const { data: rows } = await supabase.from('teams').select('competitions');
const uniqueLeagues = [...new Set(rows.flatMap(r => r.competitions))];
```

Per-team fixture polling stays the same — match-watcher already iterates per team, fetching fixtures via `?team=<api_id>&league=<id>&season=<n>`. The loop just gets a wider set of (team, league) tuples to poll.

`seasonForLeague()` in `backend/supabase/functions/_shared/league-helpers.ts` already maps `45` → current calendar year (the `default` branch). No change needed there.

### Option B — Separate `team_competitions` table

```sql
CREATE TABLE team_competitions (
  team_id TEXT REFERENCES teams(id),
  league_id INTEGER NOT NULL,
  season INTEGER NOT NULL,
  PRIMARY KEY (team_id, league_id, season)
);
```

More correct relationally, but heavier — requires a join everywhere the active-leagues query runs. Option A is simpler and the JSONB column is small (4-8 bytes per row × 71 rows = 568 bytes total).

**Recommendation: Option A.**

- `backend/supabase/functions/matchday-scheduler/index.ts` — same

## Verification

1. Apply migration 038 to dev DB, verify `competitions` column populated correctly for all 71 rows (23 clubs with `[39, 45]`, 48 countries with `[1]`).
2. Manually invoke match-watcher: confirm it polls `league=45&season=2026` for at least one PL team. Check `cron.job_run_details.return_message` for the new league count (should be 3: 39, 1, 45).
3. Wait for an actual FA Cup fixture in `match_status_state` to transition NS → FT. Verify `gd-matchday` fires and a content_item lands with `match_id` matching the FA Cup fixture.

If 3 is impractical pre-launch (the FA Cup final was the last FA Cup match of 2025-26 — next round isn't until January 2027), set up a synthetic transition test: insert a fake row into `match_status_state` with a 5-min-old `kickoff_time` and `status='FT'`, watch for the trigger.

## Out of scope for V2.1

- Multi-season `competitions` (e.g., "this team was in the Europa Conference League in 2024-25 but not 2025-26"). The JSONB column stores only current-season participation.
- Cross-country leagues (e.g., a player playing in PL while their country is in WC qualifiers). The teams table is per-entity; players are below entity granularity.
