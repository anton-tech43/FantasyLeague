## 0. Access note (read first)

Raw Postgres (`psql "$SUPABASE_DB_URL"`) failed immediately with a DNS resolution error
for the pooler host — this is the known `gd-env` egress-allowlist limitation documented
in `MAINTENANCE.md` §1 (HTTPS-to-allowlist only; port 5432/6543 not reachable), now also
confirmed from this session. **Worked around**: every check below was done via the
Supabase REST API / PostgREST (`$SUPABASE_URL/rest/v1/...` with `$SUPABASE_SERVICE_KEY`),
which is reachable. One new limitation found this run: see §5.

Caveat on this workaround: PostgREST defaults to a 1000-row page. An early pull of
`players` with no per-team filter silently truncated at 1000 of 1822 rows and produced
a false positive (looked like several top players, Haaland and Saka included, had
disappeared from their squads). Re-pulled per-team (624 rows across the 20 active
clubs, 26–38 each — matches the skill's expected range) and the false positive
disappeared. Flagging the trap in case a future run hits it with a table that's grown
past 1000 rows.
