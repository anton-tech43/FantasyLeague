## Script fix (small, safe, applied)

`scripts/verify-push-eligible.sh` unconditionally sourced `backend/.env`
(absent in the cloud, gitignored) and hardcoded the macOS Homebrew `psql`
path, so it has never actually run in `gd-env` — it fails before reaching
the network. `db-health.sh` already carries the right fallback for both.
Mirrored that same fallback into `verify-push-eligible.sh` (optional
`backend/.env` source, `psql` on `PATH` if the Homebrew path isn't
executable). This is a portability fix only — no query logic changed. It
will still time out on the Postgres-direct step until the network policy
above is fixed, but it'll now fail with a clear connection error instead of
"command not found", and will work as-is once that's fixed or when run
locally.
