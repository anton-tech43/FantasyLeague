## 8. Code-level finding: `audit-claims.ts`'s club-alias list missed the 2026-27 promoted clubs — FIXED (needs deploy)

`backend/supabase/functions/_shared/audit-claims.ts`'s `PL_ALIASES` map (used to decide
which team a claim's sentence is "about") had entries for all 20 of *last* season's
clubs including the three relegated ones (burnley, west_ham, wolves) but was missing
this season's three promoted clubs: **coventry, hull, ipswich**. Effect: `nearestTeam()`
could never resolve to `"coventry"`/`"hull"`/`"ipswich"`, so `content-audit`'s
deterministic contradiction-checker silently skipped every claim about those three clubs
(fails closed by design — "missing an alias only costs recall" — so nothing *wrong* was
shown, but 3 of 20 clubs had zero audit coverage). Same shape as the documented
Coventry/Hull content gap from the 2026-27 rollover.

This is source code, not a DB fact, so Rule 1 doesn't directly apply, but the fix is
purely additive (three new alias entries, nothing removed) and mechanically checkable,
so fixed it directly rather than only reporting it:

- Added `coventry: ["Coventry", "Coventry City"]`, `hull: ["Hull", "Hull City"]`,
  `ipswich: ["Ipswich", "Ipswich Town"]` to `PL_ALIASES`.
- Kept the three relegated clubs' aliases — removing them would let a mention of e.g.
  "Wolves" inside a current club's article get mis-attributed to the nearest *current*
  club instead of correctly failing to match anyone.
- Added a regression test to `audit-claims.test.ts` asserting a promoted club's own name
  is now a recognised alias (`relegated_but_safe` fires for a synthetic Coventry
  sentence, where before the fix it would have silently returned `[]`).
- **Could not run `deno test` in this environment** (no `deno` binary) — logic traced by
  hand against the existing regex pipeline (alias match → nearest-team gate → claim
  patterns) and is consistent with the existing passing tests' shape; please run
  `deno test backend/supabase/functions/_shared/audit-claims.test.ts` before/при deploy.
- **Not deployed** — no `supabase` CLI, no `SUPABASE_ACCESS_TOKEN`, no `backend/.env` in
  this environment (by design, per `MAINTENANCE.md` §1). The fix is committed to this
  branch; `content-audit` needs `supabase functions deploy content-audit
  --project-ref cwgpsmbunrocrofziqad --no-verify-jwt` run by a human (or a session with
  deploy credentials) to take effect.
