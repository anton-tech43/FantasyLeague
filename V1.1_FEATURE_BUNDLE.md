## How to Use This Document

This doc is a deep-dive todo. Each task carries enough context for any AI agent or developer to execute it without prior conversation context. Tasks are grouped by surface. Within a task, substeps are check-boxed and ordered.

**Status legend** (set per task by anyone working on it):
- `TODO` — not started
- `IN PROGRESS` — being worked on, claim by writing your name/handle next to the status
- `COMPLETE` — shipped and verified
- `BLOCKED` — waiting on something, note what

**Workflow for an agent picking up a task:**
1. Read the task's *Why*, *Backend work*, *iOS work*, and *Verification* sections.
2. Mark the task `IN PROGRESS` and add your handle.
3. Create or check out a branch. Naming: `claude/<short-task-slug>` (e.g., `claude/season-primer-screen`).
4. Implement substeps in order. Each substep is independently small.
5. Run the verification steps. If you cannot run them locally (e.g., iOS work on Windows), explicitly say so in the completion log.
6. Open a PR with base `claude/intelligent-thompson`. Title: `<TASK-ID>: <short summary>`.
7. After merge (or push if merge is the human's job), mark `COMPLETE` and fill in the *Completion log* at the bottom of the task with: handle, date, branch name, PR URL, notes on any deviation.

**Branch & commit conventions:**
- Branch from `claude/intelligent-thompson`.
- One task per branch when scope allows. Foundation tasks (B1, D1, D2) may share a branch.
- Commit messages: conventional sentence style, no em dashes. End with `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>`.

**Backend vs iOS:**
- Tasks tagged `[BACKEND]` are server-side (Supabase migrations, Edge Functions, pg_cron). Land these before the matching iOS work or the iOS surface will be empty.
- Tasks tagged `[iOS]` are Swift/SwiftUI.
- Many tasks have both. The substep lists below split them clearly.

**Voice & copy rules** (apply to all copy):
- No em dashes. Use commas, periods, or splits.
- Conversational, slightly cheeky. Target 22 to 35F.
- Never lecture. Never patronise.

  @MainActor
  final class CalendarSyncService {
      static let shared = CalendarSyncService()
      private let store = EKEventStore()

      enum SyncError: LocalizedError {
          case denied, noWritableSource, fetchFailed
      }

      func requestAccess() async throws -> Bool {
          try await store.requestFullAccessToEvents()
      }

      /// Creates or finds a calendar named "GoalDigger - <team>" and inserts events for every
      /// remaining fixture. Removes prior GoalDigger calendars for any other team.
      func sync(teamShortName: String, fixtures: [Fixture]) async throws {
          let title = "GoalDigger - \(teamShortName)"
          let existing = store.calendars(for: .event).first(where: { $0.title == title })
          let calendar: EKCalendar
          if let c = existing {
              calendar = c
          } else {
              guard let source = store.defaultCalendarForNewEvents?.source else {
                  throw SyncError.noWritableSource
              }
              let c = EKCalendar(for: .event, eventStore: store)
              c.title = title
              c.source = source
              try store.saveCalendar(c, commit: true)
              calendar = c
          }

          let now = Date()
          let oneYearOut = Calendar.current.date(byAdding: .year, value: 1, to: now)!
          let predicate = store.predicateForEvents(withStart: now, end: oneYearOut, calendars: [calendar])
          for event in store.events(matching: predicate) {
              try? store.remove(event, span: .thisEvent, commit: false)
          }
          try store.commit()

          for fixture in fixtures {
              let event = EKEvent(eventStore: store)
              event.calendar = calendar
              event.title = "\(teamShortName) vs \(fixture.opponent)"
              event.startDate = fixture.kickoffTime
              event.endDate = fixture.kickoffTime.addingTimeInterval(2 * 60 * 60)
              event.location = fixture.venue
              event.notes = "Match day. Open GoalDigger for prep."
              try? store.save(event, span: .thisEvent, commit: false)
          }
          try store.commit()
      }

      func removeGoalDiggerCalendars() throws {
          for c in store.calendars(for: .event) where c.title.hasPrefix("GoalDigger - ") {
              try store.removeCalendar(c, commit: false)
          }
          try store.commit()
      }
  }

      let venue: String?
  }

# Open questions and risks

- **Backend volume.** This bundle adds ~6 tables, ~7 Edge Functions, ~5 pg_cron jobs. Coordinate backend work in parallel with iOS or iOS will block.
- **Quality control on AI-generated content.** Insider items, quizzes, dossiers all need a review pass. Reuse `content-reviewer` or add a lightweight check per content type. Without this, hallucinations leak to users.
- **Tier filter location.** Client-side filtering is simpler but server-side enforcement is safer (a deliberate T3 to T1 downgrade should not still show stale T3 items from cache). Recommendation: enforce server-side for push, filter client-side for feed display.
- **GlossaryText rendering.** SwiftUI text concatenation does not support per-span tap gestures without workarounds. The agent picking up C7 should prototype the renderer early and confirm acceptable UX. Fallback option: open a dedicated glossary screen instead of a popover. Note the deviation in the completion log if you do.
- **Match-day live polling.** A 60-second poll during a live window is fine; outside it, no polling. Ensure the timer is properly torn down in `onDisappear` and `.background` scenePhase.
- **Background audio.** Listen button stops when the app backgrounds. Background audio entitlement is out of scope for v1.1; flag if user complaints justify it later.
