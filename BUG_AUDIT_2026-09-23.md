## Scope & method

- **Build:** `xcodebuild ... -scheme GoalDigger` (iPhone 17 Pro sim, iOS 26.4), current
  **working tree** — i.e. the uncommitted `CountryFollowing.isEnabled = false` change is
  in effect (country-following disabled everywhere).
- **Driving:** `xcrun simctl` install/launch + the app's own DEBUG screenshot harness
  (`-gdPresetTeam`, `-gdPresetCountry`, `-gdTab`, `-gdTeamTab`, `-gdStandingsScope`,
  `-gdMyTurn*`, `-gdLingo*`, `-gdQuiz*`). simctl cannot tap, so flows that need a tap to
  advance (onboarding interior, the context-switcher dropdown, feed→detail) were only
  partially reachable — see Coverage gaps.
- **Note on tooling:** the native Claude iOS-Simulator integration was unavailable
  (`attach` reports Xcode "installed but not selected" and wants
  `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`, which needs your
  password). Fell back to simctl + launch-arg screenshots, the documented method here.
- **Surfaces exercised:** Feed (immersive, club + cross-team), Team page (Info / Calendar
  / Table, PL + Champions League scope), My Turn (Quiz play + result, Lingo Overheard
  landing + result, Say This), Settings, onboarding entry, and the club/country/off
  permutations that the `CountryFollowing` flag governs.
- **All 20 PL clubs** were loaded on the Team → Info page and reviewed (contact sheets
  `clubs/sheetA.png` + `clubs/sheetB.png`). Header crests, opponent crests and coming-up
  cards render correctly for every club; the only per-club defect found is B6 (manager
  photos). Calendar/Table are structurally identical across clubs (verified on Arsenal).
- No app-level crash, fatal, or decode error appeared in the error log across the runs
  (only normal system/WidgetKit XPC lifecycle noise).

## Findings

### B1 — MEDIUM · Country-only user still gets the disabled country on the "His Team" tab
- **Where:** `ios/GoalDigger/App/GoalDiggerApp.swift:219` (`teamPageEntityId`
  cross-team fallback), tab label at `:231`.
- **Repro:** launch as the country-only user —
  `-gdPresetCountry netherlands -gdTab 1`.
- **Observed:** the His Team tab renders the **full Netherlands country page** (flag
  crest, "Netherlands", manager R. Koeman, "Ones to know"), and the tab is labelled
  **"Netherlands"**. Coming-up shows **"Morocco (HOME), Tue 30 Jun at 03:00"** — a WC
  fixture from **June 2026**, i.e. stale by three months (the country content pipeline is
  dead, per the flag's own doc comment).
- **Why it's a bug:** the `CountryFollowing` doc comment in `Models/Country.swift`
  states the gate means the entity is surfaced "no row in the context switcher, never the
  active context, **never the His Team tab**, and no picker in Settings." The His Team tab
  still surfaces it. When there is no club, `teamPageEntityId` falls back to
  `selectedCountry` regardless of the flag.
- **Population:** affects a user with a country and **no** club. Per the code comment
  exactly one such (dormant) production device exists, so real-world blast radius is tiny
  — but it contradicts the change's stated intent and shows stale data.
- **Contrast (works correctly):** the club+country user
  (`-gdPresetTeam arsenal -gdPresetCountry netherlands`) correctly shows **Arsenal** on
  both the switcher and the His Team tab; the country is hidden. Only the *country-only*
  case leaks.
- **Evidence:** `12_country_only_histeam.png`; contrast `14_club_country_histeam.png`,
  `11_country_only_feed.png`.

### B6 — MEDIUM · 8 of 20 PL clubs show a manager-photo placeholder (two different broken styles)
- **Where:** Team page → Info → "THE MANAGER" card, photo slot.
- **Repro:** launch each club with `-gdPresetTeam <slug> -gdTab 1`.
- **Observed:** 8 of the 20 PL clubs render a placeholder instead of a manager photo
  (confirmed persistent after an 11s load, so it is a genuinely absent image, not lag):
  - **"NO PHOTO YET"** (in-house circular grey silhouette): **Liverpool** (Iraola),
    **Crystal Palace** (Sage), **Hull City** (Jakirović), **Sunderland** (Le Bris).
  - **"image not available"** (square camera icon — off-brand, looks like a broken web
    image, not circular, does not match the avatar style): **Brentford** (Andrews),
    **Fulham** (Arbeloa), **Ipswich** (O'Neil), **Man Utd** (Carrick).
  - The other 12 clubs have proper photos (Arsenal, Aston Villa, Bournemouth, Brighton,
    Chelsea, Coventry, Everton, Leeds, Man City, Newcastle, Nottm Forest, Spurs).
- **Two bugs here:** (1) the missing photos themselves — they all correlate with managers
  appointed in 2025/2026, i.e. the photo pipeline never fetched an image for recently-set
  managers; (2) two inconsistent placeholders — the square "image not available" camera
  box looks broken/off-brand next to the intended circular "NO PHOTO YET" silhouette,
  suggesting one path is a nil URL (in-house placeholder) and the other is a
  failed/served-but-unusable image (system broken-image placeholder). Per
  `DATA_SOURCES.md` the photo CDNs return a silhouette with HTTP 200 rather than 404, so
  the "image not available" set is worth a checksum check — it may be receiving a
  placeholder image the app then fails to render as intended.
- **Evidence:** `clubs/sheetA.png`, `clubs/sheetB.png`, `clubs/verify_liverpool.png`
  ("NO PHOTO YET"), `clubs/verify_brentford.png` ("image not available").

### B2 — LOW · Fixture calendar breaks the competition label mid-word
- **Where:** Team page → Calendar, competition label column (right side of each row).
- **Repro:** `-gdPresetTeam arsenal -gdTab 1 -gdTeamTab calendar`.
- **Observed:** in the narrow right-hand column "Champions League" wraps as
  **"Champion s League"** (the word "Champions" is split across the line break) on the
  Bayern München row. "Premier League" also wraps to two lines but without splitting a
  word.
- **Fix direction:** allow the label more width, or prevent intra-word breaking (no
  hyphenation / `.lineLimit` + `.minimumScaleFactor`, or a non-breaking treatment of the
  competition name).
- **Evidence:** `03_team_calendar.png`.

### B3 — LOW · Settings: large empty band at the top of the screen
- **Where:** Settings tab.
- **Repro:** `-gdPresetTeam arsenal -gdTab 3`.
- **Observed:** the first section ("NOTIFICATIONS") starts roughly a third of the way down
  the screen, leaving a big blank region under the status bar. Reads as wasted space /
  vertical-centering rather than a deliberate layout. Worth a design confirm.
- **Evidence:** `10_settings.png`.

### B4 — LOW (needs verification on the real path) · My Turn shows the wrong module + a phantom finished round after an in-session state reset
- **Where:** `MyTurnStore.clearAll()` + `MyTurnView.applyLaunchArguments` interaction;
  the real-user twin of this path is **Settings → Delete My Data** (also calls
  `clearAll()`).
- **Repro (harness):** `-gdResetMyTurn -gdMyTurnModule quiz -gdMyTurnPack the-basics
  -gdQuizAnswer 0`.
- **Observed:** despite passing quiz args, the tab opens on **Lingo** and shows a
  **finished "You got 7 of 7"** Lingo round that was never played, with the hype card
  briefly drawn over the result heading. Passing the same module arg **without**
  `-gdResetMyTurn` correctly shows Quiz, and a **fresh install** (empty state, no reset)
  correctly defaults to Quiz — so the defect is in resetting state **while the store is
  already live**, not in the persisted default.
- **Caveat:** reproduced only via the DEBUG harness. A real user cannot pass these flags;
  the equivalent real path is Delete My Data mid-session. **Recommend verifying** whether
  a live Delete My Data leaves My Turn on the wrong module / a phantom round before
  treating this as user-facing. The hype-card overlap on its own was just mid-animation
  (the clean Lingo result screen renders fine — `08_lingo_finish.png`).
- **Evidence:** `06b_quiz_answer_retry.png`, `06c_module_quiz_only.png` (wrong module),
  vs `06f_module_quiz_back.png` / `06d_fresh_default.png` (correct).

### B5 — VERY LOW · Quiz result hype line count can mismatch the score
- **Where:** Quiz result screen (hype line).
- **Observed:** a 7/10 result (3 missed) showed the line **"Strong round. He'd have
  missed two as well."** The reassurance line references "two" while three were missed.
  Hype lines are pre-written per score bracket, so this is a copy-precision nit, not a
  logic error.
- **Evidence:** `07_quiz_finish.png`.
